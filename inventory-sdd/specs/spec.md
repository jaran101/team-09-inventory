# Spec: ฟีเจอร์แจ้งเตือนสต็อกต่ำ และรายงานมูลค่าสต็อก

## 1. เป้าหมาย (Goal)
เพิ่มความสามารถให้ระบบ inventory แจ้งเตือนผู้จัดการเมื่อสินค้าใดต่ำกว่า
threshold และให้ผู้จัดการดูรายงานมูลค่าสต็อกแยกตามหมวดหมู่ได้

## 2. User Story
| รหัส | User Story |
|---|---|
| US-01 | As a พนักงานคลังสินค้า, I want บันทึกการรับ/จ่ายสินค้าพร้อมอัปเดตสต็อกทันที, so that สต็อกในระบบสะท้อนจำนวนจริง |
| US-02 | As a ผู้จัดการ, I want รับการแจ้งเตือนทันทีเมื่อสินค้าใดต่ำกว่า threshold, so that สั่งซื้อได้ก่อนของหมด |
| US-03 | As a ผู้จัดการ, I want ดูมูลค่ารวมของสต็อกแยกตามหมวดหมู่, so that ตัดสินใจด้านการเงินได้ |
| US-04 | As a ผู้จัดการ, I Want กำหนด threshold ว่าจะสินค้านั้นๆให้ threshold มีค่าเท่าไหร่, so that ปรับเปลี่ยนขอบเขตความต้องการได้|
| US-05 | As a ผู้จัดการ, I want เพิ่มการเเจ้งเตือนสินค้าใดต่ำกว่า threshold ผ่าน Email, so that เพิ่มช่างทางการเเจ้งเตือน |

### AC ของ US-01 
Scenario: พนักงานคลังสินค้าบันทึกการรับสินค้า
  Given สินค้า "สายไฟ 2.5 sq.mm" ไม่มีสายไฟในสต็อก 
  When พนักงานบันทึกรับเข้ามา 10 เมตร
  Then สต็อกคงเหลือ 10 เมตร

Scenario: พนักงานคลังสินค้าบันทึกการจ่ายสินค้า
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 50 เมตร
  When พนักงานบันทึกจ่ายออก 10 เมตร
  Then สต็อกคงเหลือ 40 เมตร

Scenario: พนักงานคลังสินค้าบันทึกการจ่ายสินค้าเมื่อสินค้าไม่มีในสต็อก
  Given สินค้า "สายไฟ 2.5 sq.mm" ไม่มีสายไฟในสต็อก
  When พนักงานบันทึกจ่ายออก 10 เมตร
  Then ระบบส่งการแจ้งเตือนว่าไม่มีสินค้าในสต็อกเเละปฏิเสธการจ่ายสินค้า
  And ระบบส่งการแจ้งเตือนถึงผู้จัดการว่าในสต็อกไม่มีสินค้า

Scenario: พนักงานคลังสินค้าบันทึกการจ่ายสินค้าเมื่อสินค้าไม่พอ
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 12 เมตร
  When พนักงานบันทึกจ่ายออก 13 เมตร
  Then ระบบส่งการแจ้งเตือนว่าสินค้าในสต็อกไม่พอเเละปฏิเสธการจ่ายสินค้า
  And ระบบส่งการแจ้งเตือนถึงผู้จัดการว่าในสินค้าในสต็อกไม่พอ
  
### AC ของ US-03
Scenario:ผู้จัดการดูมูลค่ารวมของสต็อกแยกตามหมวดหมู่
  Given ผู้จัดการต้องการดูมูลค่ารวมของสต็อก สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 50 เมตร (เมตรละ 200 บาท)
  When ผู้จัดการใช้คำสั่งดูมูลค่ารวมของสต็อก
  Then แสดงมูลค่ารวมของหมวดหมู่อุปกรณ์ไฟฟ้า = 10,000 บาท"

### AC ของ US-04

  And ระบบส่งการแจ้งเตือนทันทีไปยังผู้จัดการว่ามีการเปลี่ยนเปลงของ threshold

Scenario:ผู้จัดการต้องการเปลี่ยนค่า threshold ในสินค้านั้นๆ กรณีที่ใส่ตัวอักษรลงไป
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 50 เมตร และ threshold = 15
  When ผู้จัดการใช้คำสั่งเเก้ไขค้า threshold ที่ไม่ใช่ตัวเลข
  Then ระบบปฏิเสธการอัปเดต และคืนค่า Error Message"กรุณากรอกค่าเป็นตัวเลข"

  Then ระบบปฏิเสธการอัปเดต และคืนค่า Error Message"กรุณากรอกตัวเลขที่มากกว่า 0"

Scenario:ผู้จัดการต้องการเปลี่ยนค่า threshold ในสินค้านั้นๆ ในกรณีที่เเก้ไขค่า threshold แล้วจำนวนสินค้าในสต็อกมีค่าน้อยกว่า threshold
  Given สินค้า "สายไฟ 2.5 sq.mm" มีสต็อก 18 เมตร และ threshold = 15
  When ผู้จัดการใช้คำสั่งเเก้ไขค้า threshold = 20
  Then แก้ไขค่า threshold ของ สายไฟ 2.5 sq.mmในระบบเป็น threshold = 20
  And ระบบส่งการแจ้งเตือนทันทีไปยังผู้จัดการว่ามีการเปลี่ยนเปลงของ threshold และแจ้งเตือนว่าสินค้าในสต็อกต่ำ

## 4. In Scope / Out of Scope
**In Scope:** บันทึกรับ/จ่าย + อัปเดตสต็อกใน memory, แจ้งเตือน email/sms (print แทนส่งจริง), รายงานมูลค่าแยกหมวด ,
**Out of Scope:** ส่ง email/sms จริง, ระบบ login/สิทธิ์, ฐานข้อมูลถาวร

## 5. Functional Requirements (FR)
| รหัส | ความต้องการ | จาก Story |
|---|---|---|
| FR-01 | ระบบต้องอัปเดตสต็อกทันทีหลังบันทึกรับ/จ่าย | US-01 |
| FR-02 | ระบบต้องตรวจสต็อกก่อนจ่าย และปฏิเสธถ้าไม่พอ | US-01 |
| FR-03 | ระบบต้องแจ้งเตือนเมื่อสต็อกหลังจ่ายต่ำกว่า threshold | US-02 |
| FR-04 | ระบบมีความยืดหยุ่นสามารถปรับค่า threshold ได้ | US-04 |

## 6. Non-Functional Requirements (NFR)
| รหัส | มิติ | ความต้องการ (ต้องวัดได้) |
|---|---|---|
| NFR-01 | Performance | รายงานมูลค่าสต็อก 1,000 รายการเสร็จภายใน 1 วินาที |
| NFR-02 | Maintainability | เพิ่มช่องทางแจ้งเตือนใหม่ได้โดยไม่แก้ business logic เดิม |
| NFR-03 | Availability/Reliability | ระบบต้องสามารถรองรับการแก้ไข threshold พร้อมกันหลายรายการได้ โดยข้อมูลไม่สูญหายหรือเกิดภาวะ Data Corruption|

## 7. Design Notes
- การแจ้งเตือนต้องแยกออกจาก business logic ของสต็อก
- คาดว่าจะมีหลายช่องทางแจ้งเตือน ควรออกแบบให้เพิ่มได้ง่าย
