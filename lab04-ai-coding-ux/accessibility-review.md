## 2. บันทึกการวิเคราะห์ข้อผิดพลาดของ AI และการแก้ไข (Rubric Requirement)

ตามเกณฑ์ Rubric ได้ระบุจุดที่ AI ทำพลาดในงานออกแบบ UI พร้อมเก็บประวัติข้อมูลเดิมที่ AI สร้างไว้ (Before) และสิ่งที่ทีมได้ดำเนินการแก้ไข (After) ดังนี้:

### จุดที่ 1: สีข้อความคำใบ้และข้อมูลรอง (Hint Text) มี Color Contrast ต่ำเกินไป (ไม่ผ่านเกณฑ์ WCAG AA)

* **สิ่งที่ AI ให้มา (Before):**
  * AI กำหนดสีข้อความคำอธิบายเพิ่มเติมใต้ช่องกรอก (Hint Text) และปุ่มควบคุมที่ไม่แอคทีฟด้วยสีเทาอ่อน `#9CA3AF` (Tailwind Gray-400) ขนาดฟอนต์ 11px เช่น:
    * `lg-email-hint`: `*(ตัวอย่าง: user@company.com)` (สี `#9CA3AF`)
    * `ap-f8-hint`: `(จำนวนชิ้น/ม้วนในคลังปัจจุบัน)` (สี `#9CA3AF`)
    * `ap-f9-hint`: `(ระบบจะเตือนเมื่อสินค้าเหลือเท่านี้หรือน้อยกว่า)` (สี `#9CA3AF`)
    * `pag-prev`: `‹ ก่อนหน้า` (สี `#9CA3AF`)
* **ปัญหาด้าน Accessibility (WCAG 1.4.3 Contrast Minimum):**
  * สี `#9CA3AF` เมื่ออยู่บนพื้นหลังสีขาว `#FFFFFF` หรือพื้นเทาอ่อน `#F9FAFB` มีอัตราส่วน Contrast เพียง **2.54:1** ซึ่งต่ำกว่ามาตรฐาน WCAG 2.1 AA ที่กำหนดให้ข้อความปกติขนาดเล็กต้องมี Contrast ไม่ต่ำกว่า **4.5:1** ทำให้ผู้ใช้งานที่มีปัญหาด้านสายตา หรือใช้งานในโกดังคลังสินค้าที่มีแสงสะท้อน อ่านข้อความได้ยากมาก
* **สิ่งที่แก้ไข (After & Fixes Applied):**
  * ปรับเปลี่ยนรหัสสีของข้อความ Hint Text ทั้งหมดเป็น `#4B5563` (Tailwind Gray-600) ซึ่งให้ Contrast Ratio สูงถึง **7.0:1** บนพื้นขาว (ผ่านเกณฑ์ WCAG AAA/AA)
  * ปรับขนาดฟอนต์จาก 11px เพิ่มเป็น 12px เพื่อให้อ่านง่ายและชัดเจนยิ่งขึ้น

### จุดที่ 2: การใช้ Placeholder แทน Visible Label ในช่องค้นหาบน Dashboard

* **สิ่งที่ AI ให้มา (Before):**
  * ในหน้า Dashboard ส่วนแถบค้นหา AI วางกล่อง Input ที่มีค่า Value เป็น `🔍 ค้นหาสินค้า / SKU...` (`search-input`) โดยไม่มี Label อยู่ด้านบนหรือด้านหน้ากล่องข้อความ
* **ปัญหาด้าน Accessibility (WCAG 3.3.2 Labels or Instructions & WCAG 1.3.1 Info and Relationships):**
  * การใช้เพียง Placeholder ในการระบุหน้าที่ของช่องกรอก เมื่อผู้ใช้งานพิมพ์ข้อมูลลงไป ข้อความ placeholder จะหายไป ส่งผลให้ผู้ใช้ลืมบริบทว่ากำลังกรอกข้อมูลอะไร และโปรแกรมอ่านหน้าจอ (Screen Reader) อาจไม่สามารถประกาศชื่อช่องกรอกได้อย่างถูกต้อง
* **สิ่งที่แก้ไข (After & Fixes Applied):**
  * เพิ่มการกำกับ Accessible Name ให้กับกล่องค้นหาอย่างชัดเจน เช่น กำหนด `aria-label="ค้นหารายการสินค้าหรือรหัส SKU"`
  * ปรับสีข้อความ Placeholder ให้เข้มขึ้นเป็น `#4B5563` เพื่อไม่ให้จางจนมองไม่เห็น

## 3. สรุปภาพรวมและข้อเสนอแนะในการพัฒนา (Implementation Guidelines)

1. **Semantic HTML & ARIA:**
   * เมื่อนำแบบร่าง UI ไปพัฒนาเป็นหน้าเว็บจริง (HTML/CSS) ต้องใช้แท็ก `<label for="...">` ผูกกับ `id` ของ `<input>` เสมอ
   * ใช้ปุ่ม `<button type="submit">` หรือ `<button type="button">` ห้ามใช้ `<div>` ทำปุ่มคลิก เพื่อให้สามารถใช้ปุ่ม `Tab` และ `Enter/Space` ในการควบคุมได้
2. **Keyboard Navigation & Focus Indicator:**
   * ต้องกำหนด `:focus-visible` ของทุกฟิลด์และปุ่มให้มี Outline สีฟ้า/น้ำเงินชัดเจน (เช่น `outline: 2px solid #2563EB; outline-offset: 2px;`) ไม่ตัด `outline: none` ทิ้ง
3. **Form Error Handling:**
   * ฟิลด์ที่กรอกผิดต้องมีแอตทริบิวต์ `aria-invalid="true"` และเชื่อมโยงข้อความแจ้งเตือนด้วย `aria-describedby="error-message-id"`
