### (1) เมธอด `batch_sell(orders: dict[str, int]) -> dict[str, int]`

* **Docstring บอกว่าอะไร แล้วโค้ดทำตามนั้นจริงหรือไม่?**
  * *Docstring:* ตัดสต็อกสินค้าหลายรายการพร้อมกัน คืนค่าสต็อกที่เหลือของแต่ละรายการ
  * *ความเป็นจริง:* ไม่ทำตามอย่างสมบูรณ์ เพราะขาดการตรวจสอบขอบเขตค่า `amount <= 0` และไม่ได้ทำให้เป็น Atomic Operation (ถ้าพังกลางทางจะไม่ Rollback)
* **ถ้าทำงานสำเร็จไปครึ่งทางแล้วเกิด error จะเหลือ state ค้างไว้แบบไหน?**
  * *ผลกระทบ:* เกิด state ค้างแบบ **Inconsistent / Partial Cut** คือรายการแรกๆ ใน Loop ที่ตัดสำเร็จจะถูกลดจำนวนใน `self._inv` ไปแล้ว แต่รายการหลังที่พังจะเกิด Exception ส่งผลให้สต็อกถูกตัดออกไปบางส่วนโดยที่ Transaction ไม่สมบูรณ์
* **ถ้ามีสอง thread เรียกพร้อมกัน ค่าที่อ่านมาก่อนยังใช้ได้อยู่หรือไม่?**
  * *ผลกระทบ:* ใช้ไม่ได้ (เกิด Race Condition) เพราะไม่มีการใช้ Lock ปกป้องช่วงการตรวจสอบและตัดสต็อก หาก 2 Threads อ่านสต็อกเดียวกันพร้อมกัน ทั้งคู่จะคิดว่าสต็อกพอ แล้วหักสต็อกซ้ำซ้อนจนสต็อกติดลบได้
* **ถ้าไม่มีข้อมูลเลย บรรทัดที่มีการหารจะพังหรือไม่?**
  * *ผลกระทบ:* เมธอดนี้ไม่มีการทำงานเกี่ยวกับการหาร

### (2) เมธอด `apply_discount(name: str, percent: float) -> float`

* **Docstring บอกว่าอะไร แล้วโค้ดทำตามนั้นจริงหรือไม่?**
  * *Docstring:* คำนวณราคาสินค้าหลังหักส่วนลดเป็นเปอร์เซ็นต์ (0-100)
  * *ความเป็นจริง:* **ไม่ทำตามข้อกำหนดเรื่องขอบเขตของค่า (Boundary)** เพราะไม่มี Validation ตรวจสอบค่า `percent` ให้ติดลบได้ (เช่น `-20`) หรือเกิน 100 ได้ (เช่น `150`) ทำให้ราคาสินค้าเพิ่มขึ้นหรือติดลบได้
* **ถ้าทำงานสำเร็จไปครึ่งทางแล้วเกิด error จะเหลือ state ค้างไว้แบบไหน?**
  * *ผลกระทบ:* เป็น Pure Function/Read-only คำนวณแล้วคืนค่า ไม่ได้เปลี่ยน State ในระบบ จึงไม่เกิด State ค้าง
* **ถ้ามีสอง thread เรียกพร้อมกัน ค่าที่อ่านมาก่อนยังใช้ได้อยู่หรือไม่?**
  * *ผลกระทบ:* ค่าที่อ่านมาอาจล้าสมัย (Stale Data) หากอีก Thread เปลี่ยนราคาสินค้า หรือลบสินค้าออกจากคลังไประหว่างที่กำลังคำนวณ
* **ถ้าไม่มีข้อมูลเลย บรรทัดที่มีการหารจะพังหรือไม่?**
  * *ผลกระทบ:* บรรทัดที่มีการหาร `percent / 100` ใช้ตัวหารเป็นค่าคงที่ `100` เสมอ จึงไม่เกิด `ZeroDivisionError`

### (3) เมธอด `restock_bulk(items: dict[str, int]) -> dict[str, int]`

* **Docstring บอกว่าอะไร แล้วโค้ดทำตามนั้นจริงหรือไม่?**
  * *Docstring:* เติมสต็อกสินค้าหลายรายการพร้อมกัน
  * *ความเป็นจริง:* ไม่ทำตามอย่างสมบูรณ์ เพราะไม่ได้ตรวจสอบขอบเขตค่า `amount <= 0` (เปิดโอกาสให้ใส่ค่าติดลบเพื่อแอบลดสต็อกได้) และหากมีชื่อสินค้าที่ไม่มีในระบบ จะพังกลางทางทันที
* **ถ้าทำงานสำเร็จไปครึ่งทางแล้วเกิด error จะเหลือ state ค้างไว้แบบไหน?**
  * *ผลกระทบ:* เหลือ state ค้างแบบ **Partial Restock** รายการสินค้าก่อนหน้าจะถูกเพิ่มสต็อกไปแล้ว แต่รายการที่เหลือจะไม่ถูกเพิ่ม ทำให้ข้อมูลสต็อกไม่ตรงกับใปรับเข้าจริง
* **ถ้ามีสอง thread เรียกพร้อมกัน ค่าที่อ่านมาก่อนยังใช้ได้อยู่หรือไม่?**
  * *ผลกระทบ:* ใช้ไม่ได้ (Race Condition) เนื่องจากอ่านค่า `current` มาไว้ในตัวแปร local แล้วค่อยบวกเพิ่ม หากมีอีก Thread มาแก้ไขค่าในช่วงเวลานั้น ค่าสต็อกที่เขียนทับจะสูญหาย (Lost Update)
* **ถ้าไม่มีข้อมูลเลย บรรทัดที่มีการหารจะพังหรือไม่?**
  * *ผลกระทบ:* เมธอดนี้ไม่มีการทำงานเกี่ยวกับการหาร

### (4) เมธอด `average_unit_value() -> float`

* **Docstring บอกว่าอะไร แล้วโค้ดทำตามนั้นจริงหรือไม่?**
  * *Docstring:* คืนค่าเฉลี่ยต่อชิ้นของสินค้าทั้งคลัง
  * *ความเป็นจริง:* โค้ดพยายามคำนวณมูลค่ารวมหารด้วยจำนวนชนิดสินค้า แต่วิธีการคำนวณไม่ตรงตาม Logic ค่าเฉลี่ยต่อชิ้นจริง (ไปหารด้วยจำนวนชนิดสินค้า ไม่ใช่จำนวนชิ้นทั้งหมด) และพังทันทีเมื่อคลังว่างเปล่า
* **ถ้าทำงานสำเร็จไปครึ่งทางแล้วเกิด error จะเหลือ state ค้างไว้แบบไหน?**
  * *ผลกระทบ:* เป็นการคำนวณเพื่ออ่านค่าอย่างเดียว (Read-only) ไม่มีผลกระทบต่อ State
* **ถ้ามีสอง thread เรียกพร้อมกัน ค่าที่อ่านมาก่อนยังใช้ได้อยู่หรือไม่?**
  * *ผลกระทบ:* หากมี Thread อื่นกำลังเพิ่ม/ลบสินค้าใน `_items` ขณะรัน อาจเกิด `RuntimeError: dictionary changed size during iteration` หรือได้ค่าที่ไม่เสถียร
* **ถ้าไม่มีข้อมูลเลย บรรทัดที่มีการหารจะพังหรือไม่?**
  * *ผลกระทบ:* **พังทันที (Critical Error)** เกิด `ZeroDivisionError` เพราะเมื่อไม่มีสินค้าในระบบ `len(self._inv._items)` จะเป็น `0` ทำให้บรรทัด `total_value / total_items` หารด้วยศูนย์

### Comment 1: `batch_sell` — ขาด Atomicity & Transaction Rollback
* **ตำแหน่ง:** เมธอด `batch_sell` บรรทัดที่ 12–18
* **เหตุผลที่ผิด:** เมธอดไม่มีการตรวจสอบความพร้อมของสต็อกทุกรายการก่อนตัดจริง (Validation Phase) และไม่มีระบบ Rollback ทำให้การทำรายการไม่เป็น Atomic Transaction
* **กรณีที่จะพัง (Case & Sample Input):**
  * **สถานะระบบเริ่มต้น:** สินค้า A มีสต็อก `10` ชิ้น, สินค้า B มีสต็อก `2` ชิ้น
  * **Input:** `orders = {"สินค้า A": 5, "สินค้า B": 10}`
  * **พฤติกรรมที่พัง:** Loop รายการแรก สินค้า A จะถูกหักสต็อกเหลือ `5` ชิ้นสำเร็จ แต่เมื่อเข้า Loop รายการที่สอง สินค้า B มีไม่พอ จะเกิด `ValueError` พ่นออกมาทันที ส่งผลให้การทำรายการยกเลิก แต่สต็อกของ สินค้า A ถูกหักค้างไว้เรียบร้อยแล้วโดยไม่ได้คืนค่า (Partial Cut)
* **ข้อเสนอแนะในการแก้:** ปรับให้ทำการ Validate สต็อกและตรวจจับ `KeyError`/`ValueError` ของทุกรายการให้ผ่านก่อน หรือใช้ `with self._lock:` ร่วมกับ Context Manager เพื่อทำการ Rollback หากเกิด Exception

### Comment 2: `apply_discount` — ขาด Boundary Validation ของเปอร์เซ็นต์ส่วนลด
* **ตำแหน่ง:** เมธอด `apply_discount` บรรทัดที่ 22–25
* **เหตุผลที่ผิด:** ไม่มีการตรวจสอบขอบเขตค่าของพารามิเตอร์ `percent` ( Boundary Check) ว่าอยู่ในช่วง `0` ถึง `100` ตามข้อกำหนดหรือไม่
* **กรณีที่จะพัง (Case & Sample Input):**
  * **กรณีที่ 1 (ส่วนลดติดลบ):** `apply_discount("สายไฟ", -50.0)`  
    * **ผลลัพธ์:** ราคาสินค้าจะกลายเป็น $200 \times (1 - (-0.5)) = 300$ บาท (ราคาสินค้าเพิ่มขึ้นแทนที่จะลดลง)
  * **กรณีที่ 2 (ส่วนลดเกิน 100%):** `apply_discount("สายไฟ", 150.0)`  
    * **ผลลัพธ์:** ราคาสินค้าจะกลายเป็น $200 \times (1 - 1.5) = -100$ บาท (ราคาสินค้าติดลบ ระบบขาดทุน)
* **ข้อเสนอแนะในการแก้:** เพิ่ม Guard Clause ตรวจสอบค่า `percent` ที่รับเข้ามา หาก `not (0 <= percent <= 100)` ให้ `raise ValueError("เปอร์เซ็นต์ส่วนลดต้องอยู่ระหว่าง 0 ถึง 100")`

### Comment 3: `restock_bulk` — เกิด Race Condition และเสี่ยงต่อการถูกแทรกแซง Data
* **ตำแหน่ง:** เมธอด `restock_bulk` บรรทัดที่ 30–35
* **เหตุผลที่ผิด:** มีการอ่านค่าสต็อกปัจจุบันมาเก็บไว้ในตัวแปร local (`current = ...`) แล้วค่อยนำมาบวกเพิ่มเพื่อเขียนกลับ โดยไม่มีการล็อกสายการทำงาน (Thread Lock) ทำให้เสร็จสิ้นแบบ Thread-unsafe
* **กรณีที่จะพัง (Case & Sample Input):**
  * **สถานะระบบเริ่มต้น:** สินค้า A มีสต็อก `50` ชิ้น
  * **Thread 1:** เรียก `restock_bulk({"สินค้า A": 10})` -> อ่าน `current = 50`
  * **Thread 2 (แทรกเข้ามา):** เรียก `sell("สินค้า A", 5)` -> หักสต็อกเหลือ `45` ชิ้น
  * **Thread 1 (ทำงานต่อ):** เขียนค่า `50 + 10 = 60` ทับลงไปในระบบ
  * **ผลลัพธ์ที่พัง:** ผลการขายของ Thread 2 สูญหายไปทันที (Lost Update) สต็อกจริงควรเป็น `55` แต่ระบบบันทึกเป็น `60`
* **ข้อเสนอแนะในการแก้:** นำ `threading.Lock()` เข้ามาครอบทั้งบล็อกการอ่านและเขียนค่าสต็อก หรือเรียกใช้เมธอด atomic `restock()` ของคลาส `Inventory` โดยตรง

### Comment 4: `average_unit_value` — เกิด `ZeroDivisionError` เมื่อคลังสินค้าว่างเปล่า
* **ตำแหน่ง:** เมธอด `average_unit_value` บรรทัดที่ 40–43
* **เหตุผลที่ผิด:** ไม่มีการตรวจสอบตัวหารก่อนคำนวณ เมื่อไม่มีสินค้าในคลัง ตัวหาร `len(self._inv._items)` จะเป็น `0` ทำให้โปรแกรม Crash
* **กรณีที่จะพัง (Case & Sample Input):**
  * **สถานะระบบเริ่มต้น:** `self._inv._items = {}` (คลังสินค้าเพิ่งสร้างใหม่ ยังไม่มีรายการสินค้าใดๆ)
  * **Input/Execution:** เรียก `service.average_unit_value()`
  * **ผลลัพธ์ที่พัง:** เกิด `ZeroDivisionError: division by zero` ทำให้ระบบ Crash ทันที
* **ข้อเสนอแนะในการแก้:** เพิ่มการตรวจสอบ `if not total_items:` หรือ `if total_items == 0:` ให้คืนค่า `0.0` กลับไปทันที เพื่อป้องกันการหารด้วย zero
